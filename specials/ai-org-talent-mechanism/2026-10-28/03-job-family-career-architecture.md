# 2026-10-28｜专题三：岗位、族群、序列的持续建设

> **严格研究窗口：**2026-10-27 18:00—2026-10-28 18:00（Asia/Shanghai）。只有日期、没有精确时分的材料可以作为本轮首次接收，但不据此宣称一定落入窗口。
>
> **本期证据结论：**严格窗口内可核的“新岗位／新职族／新职业序列正式制度”仍为 **0**。今日有一个值得研究但尚未上线的规划产品根：Dayforce把业务任务、技能、岗位结构、人员与智能体成本放进同一情景模拟；另有TalentLMS调查与一份国内初级AI招聘文本，分别提示旧工作不退出、复合岗位缺支持的风险。三者都不能证明新序列已经成立，也不能支持自动减编、定薪或晋升。

## 读者应该带走什么

| 业务问题 | 今日答案 | 管理含义 |
|---|---|---|
| AI让任务不断变化，要不要马上新建序列？ | 不要。今日没有正式制度；Dayforce披露的也是先从“要完成什么工作”出发，再模拟技能、岗位与结构 | 先拆任务、决定权、人工复核和工作退出，再用现有岗位＋技能标签＋项目角色试运行 |
| 一个初级岗位写了原型、数据、检索增强、测试和文档，是否说明“复合型岗位”已成熟？ | 不能。单份招聘文本只证明招聘承诺，未证明导师容量、实际分工、正常工时和任职结果 | 岗位变宽时必须同步写清协助／独立交付边界、专家接口、学习时间和异常接手 |
| AI技能培训完成，能否直接写入职级或薪酬？ | 不能。TalentLMS调查中，部分员工仍回到旧流程，原因包括旧方式更快、核验返工多；课程完成不等于技能转化 | 用真实任务质量、返工和可复核成果验证技能；不以课程、证书或调用量自动定薪晋升 |
| 业务说“建序列”，可能真正想解决什么？ | 常混合长期责任、短期稀缺、项目贡献、持续附加负担和留任个案 | 分别选择岗位重评、技能标签、稀缺系数、项目激励、津贴或薪带调整，不用永久身份解决短期价格 |
| 什么时候应坚决不新增序列？ | 只有热词、单人需求、短项目、培训活动、产品模拟、招聘广告或少数人加价时 | 先用可撤销机制；稳定责任、复数需求、多级复杂度、共同评审和长期流动同时成立后才评审序列 |

## 1. 今日一句话专题判断

AI时代岗位架构的稳妥顺序是 **先把工作拆到任务、决定权、风险和停止项，再在现有岗位上配置动态技能与项目角色，最后才把稳定、复数、多级且可共同评审的责任固化为岗位／职族／序列**；今日新增材料增强了“工作优先、结构后置”的判断，没有新增高置信制度结论。

## 3. 今日核心判断

### 判断一：从“工作问题”开始优于从人数或热词开始，但规划模型不能替代岗位治理

- **可信度：中。**官方产品逻辑可核，产品尚未可用且没有客户后效。
- **证据基础：**Dayforce称规划者可以先写业务问题，再调整岗位、结构、技能、人员与智能体假设；公告明确战略规划智能体预计2027年第一季度可用。[1]
- **为什么重要：**这增强了“先任务、后岗位”的设计顺序，却没有回答假设来自哪里、员工能否纠错、谁批准结构变化。模型输出只能用于讨论方案，不能直接成为个人排名、减编或调薪指令。

### 判断二：岗位变宽之前必须删旧工作并配置复核能力，否则“复合型人才”只是劳动加码

- **可信度：中。**调查是供应商横截面自报，不能证明因果，但反向信息与工作设计问题直接相关。
- **证据基础：**TalentLMS样本中，有人回到旧方式是因为更快；不持续使用AI者还报告检查与返工过多。调查同时显示培训完成与实际工作使用存在差距。[2][3]
- **为什么重要：**岗位说明增加“会用AI”不能自动带来生产率。岗位重写必须同时说明哪些旧任务停止、错误谁复核、学习是否在正常工时，以及节省的时间是否返还员工或用于更高价值工作。

### 判断三：一份宽任务JD可以发现岗位设计问题，不能证明新岗位族或双通道制度成立

- **可信度：中高（对证据边界），低（对实际运行）。**招聘页正文可读，但首次发布、导师容量和兑现结果未知。
- **证据基础：**该初级岗位同时覆盖原型、数据、集成、检索、测试和文档，并列技术／管理通道；文本没有披露哪些任务在指导下完成、何时独立、谁提供专业复核。[4]
- **为什么重要：**头衔相同不等于责任相同，广告中的“通道”也不等于可申诉的晋升制度。应先把协助、独立交付和高风险签署分级，再决定岗位级别与培养投入。

### 判断四：结果责任变宽和专业门槛变深仍会并存，岗位架构要保留两条轴

- **可信度：中高（跨日综合判断），今日无新强制度证据。**
- **证据基础：**Dayforce把任务、技能和岗位分开建模，国内JD展示端到端任务扩展；昨日材料仍显示岗位化培养与专业路径并存，今日没有证据支持把专业序列一并合并。[1][4][6]
- **为什么重要：**岗位族可维持共同专业根，端到端项目责任可由跨职族项目角色承担。用单一“AI通才序列”吞掉深专业，会使培养、复核、定价和职业认同都失真。

### 判断五：新序列申请必须先拆成“责任、技能、价格、项目和负担”五类问题

- **可信度：中高（治理方法），今日没有企业样本支持发生率。**
- **证据基础：**今日材料分别涉及结构模拟、技能转化和复合任务，没有一项公开了完整新序列；内部知识库也持续将长期岗位价值、技能、市场稀缺、项目贡献和附加责任分开。[7][8]
- **为什么重要：**留关键人、补短期市场价、奖励战役成果、补偿双轨运行和建立长期职业共同体不是同一问题。把它们全部包装成新序列，会制造头衔膨胀、永久成本与内部公平债务。

## 4. 重点案例事实还原：Dayforce把工作、技能与结构放进同一规划对话

| 还原维度 | 已披露事实 | 仍缺什么／争议 |
|---|---|---|
| 背景 | 厂商认为传统人员规划常从人数倒推；当人员和智能体共同完成工作时，应先问业务需要完成什么 | 这是厂商问题定义，不是客户已经验证的共同痛点 |
| 时间线 | 2026年10月27日发布；部分Dayforce智能体能力已可用，战略人员规划智能体预计2027年第一季度可用 | 没有测试范围、正式上线日、客户名单与版本记录 |
| 起点 | 用户可用自然语言从业务问题开始，讨论工作如何由人员、智能体或共同完成 | 没有说明问题模板、岗位承担者参与程度和否决权 |
| 模拟对象 | 人员、技能、组织结构、岗位、成本与产出；可以增改岗位、改变结构和生产率假设 | 没有披露技能数据来源、缺失与偏差、更正机制和历史岗位版本 |
| 成本口径 | 公告称同时看人数成本与智能体令牌成本 | 令牌成本不是部署、监督、错误、维护、培训、合规和退出的全部成本 |
| 结果呈现 | 厂商称可以实时查看二阶、三阶影响，并把规划连接到执行 | 未披露影响模型、误差、可解释性、独立审计和误操作恢复 |
| 人事边界 | 公告主张帮助规划人员与智能体组合 | 没有承诺模型不得自动排名、减编、定薪或晋升，也未披露员工知情和申诉 |
| 员工影响 | 公告没有提供员工少做了哪些重复工作、学习工时、自主权或收益分配 | 因此不能称产品改善工作体验或提高人才密度 |
| 可借鉴点 | 从任务与价值开始；把技能、岗位、结构和多类成本放在同一讨论中；显式展示假设 | 借鉴的是讨论顺序与可见性，不是产品已经验证的算法 |
| 不可照搬点 | 不把令牌价格当全成本，不把岗位匹配分当人员价值，不由模拟直接触发减编、调薪与晋升 | 高影响决定必须有具名责任人、人工复核、员工更正和申诉 |

**案例结论：**Dayforce提供的是一个2027年才计划开放的规划界面，不是岗位改革成效。它最有价值的增量，是把“先问工作要完成什么”公开写成产品逻辑；最大空白，是数据与假设如何被实际岗位承担者纠正，以及模拟结果如何与正式人事权力隔离。

## 5. Context层：今日背景材料、弱信号、反例和冲突信息

> **暂不形成结论，但提示我们关注……**

1. **日期不等于严格落窗。**Dayforce、TalentLMS、Gartner和国内JD页面均标2026年10月27日，但未核到精确时分；它们可作为本轮首次接收材料，不据此宣称一定晚于北京时间18:00。
2. **规划粒度更细不等于结论更真。**岗位、技能、人员和成本字段越多，越需要核数据来源、遗漏、纠错和决定权；一张精细模拟图不能代替工作现场验证。
3. **“回到旧流程”不必然是抗拒改变。**旧方式可能更快，新工具可能增加核验；也可能是缺练习或团队仍用旧方式。调查不能区分全部因果，但足以反对用采用率给个人贴“不适应”标签。[2]
4. **初级复合岗是重要弱信号和风险信号。**广任务可能提供端到端成长，也可能把数据、开发、测试、文档和支持压给新人；没有导师、工时与错误接手，不能把“复合”写成人才密度提升。[4]
5. **管理层减少有结构性反例。**Gartner框架提醒，行政整理可以自动化，但异常发现、辅导、信任和跨团队协调不应一起消失；今天仍没有可量化的企业后效。[5]
6. **招聘薪酬证据不足。**一份实习3000—4000元／月、初级正式6000—8000元／月的文本，缺税口径、奖金、发薪月数、同岗基准与实际录用，不能年化或推算AI技能溢价。[4]
7. **国内制度与指定公众号覆盖仍缺。**没有取得国内企业岗位族、任职资格、序列、薪带审批原件，也未取得「AI组织进化论」微信原文；准确表述是“覆盖未完成”，不是“没有更新”。
8. **AI会放大既有管理模式。**规划工具既可让选择更透明，也可把偏见更快变成人事动作；岗位重设计必须先证明员工少做了什么、是否增加自主权和是否公平分享收益。

## 7. 对我们行动的启发：落地启发

### 7.1 先维护四层架构

1. **岗位骨架层：**只放预计稳定12—18个月的结果、决定权、风险、专业深度、协作接口、工作负担和必要人工复核。
2. **动态技能层：**用真实任务成果验证技能，标明用途、来源、有效期和更正方式；课程、证书、调用量只能证明活动发生。
3. **项目角色层：**为阶段性端到端责任写清权限、专家资源、交接、停止和退出；项目结束后角色可撤销。
4. **价格层：**把市场稀缺、项目成果、持续附加责任、迁移期负担和岗位长期升值分别处理，每一种都有复核或退出条款。

### 7.2 什么时候采用哪种机制

| 真实问题 | 优先机制 | 进入条件 | 什么时候坚决不新增序列 |
|---|---|---|---|
| 出现长期独立结果责任 | **新建岗位** | 去掉AI热词后仍预计稳定12—18个月；产出、权限、风险、接口清楚；有复数需求 | 单人、短项目、单客户、临时兼任、产品模拟或只有招聘宣传 |
| 多个稳定岗位共享专业根 | **新建职族** | 共享人才市场、方法、培养、评价、定价和横向流动 | 只因为头衔都带AI、智能体、架构师或产品 |
| 专业贡献需要独立成长 | **新建职业序列** | 至少三级真实复杂度；有共同评审、薪带、晋升、转入转出和申诉 | 为关键人留任、个案晋升、绕预算或给少数人加价 |
| 能力跨岗且快速变化 | **技能标签／项目资格** | 真实成果验证；用途、来源、有效期和人工等价证据明确 | 用课程参与、工具采用、证书签到或私人数据自动定薪晋升 |
| 同岗同级同地短期难招 | **市场稀缺系数** | 有可比报价与内部公平证据；6—12个月复核／退出 | 把一轮招聘困难永久写进职级或基本资格 |
| 战役型额外成果 | **项目激励** | 事前约定里程碑、质量、风险和团队共同贡献 | 替代长期岗位价值，或只奖励最可见负责人 |
| 持续认证、值守、复核或风险签署 | **专项津贴** | 附加责任可审计，有工时、资源和专业支持 | 购买无限责任、强制学习或隐性加班 |
| 迁移期双轨运行／临时高负荷 | **临时补贴** | 起止、对象、旧任务退出和转换规则清楚 | 用“临时”长期拖延编制与负荷问题 |
| 整个岗位价值长期上移 | **薪酬带宽调整／岗位重评** | 同岗同级同地持续证据、职责变化、内部公平与预算同时成立 | 只抬新招上限，或用换头衔掩盖少数人加价 |
| 只有热词、单岗、培训、模拟、少量JD或现有机制可解决 | **坚决不新增岗位／职族／序列** | 退回责任包、带薪学习、技能标签、项目角色或可逆价格试验 | 为显得重视AI、制造晋升空间或转移旧薪酬问题 |

### 7.3 90天最小试点

1. 选一个现有岗位，与任职者共同列出AI前后的任务、决定权、专家接口、异常接手、旧任务停止和学习时间；不新增个人日报。
2. 岗位与职族先不改，只增加有90天有效期的技能标签和项目角色；学习、试错、复盘及人工复核计入正常工时。
3. 业务经理、专业专家、HR和员工共同确认谁拍板、谁辅导、谁能停止、谁能更正技能记录；高影响人事决定不由模型分数自动触发。
4. 用已有质量、返工、等待、事故、工时和自愿反馈看员工是否真的少做重复劳动、获得更高自主权；省时不能自动转成额外工作量。
5. 90天只决定继续、调整或停止。连续两个业务周期出现稳定责任、复数需求、多级复杂度和独立市场后，再进入永久岗位／职族／序列评审。
